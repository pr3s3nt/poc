# Definition-selected score-k8s rendering — local verification

## Scope and environment

Branch `implement_template_engine`; user authorized full registration → Preview
→ Deploy integration for internal-k8s. No commit/push or external infrastructure
mutation is included. Local score-k8s 0.15.0 was available on PATH; its binary
SHA-256 is `52b7fb666f702b21f9d5433380bd4d8ac91a3192dd5e1f3b9c6a141a861d99dd`.
Tests use fake provisioning/delivery, private temporary CLI workspaces and
isolated JSON state. They do not prove cluster readiness or real database reuse.

## Observations

- Catalog rejects unavailable bundles, cloud/wrong-type pairs, connection,
  co-provisioning and arbitrary template/command inputs. Registration captures
  the bundle fingerprint. Duplicate registration remains insert-only.
- Pure planning selects the weighted workload Definition, rejects ties and
  missing/changed bundles, and changes plan hashes when rendering intent changes.
  Existing infrastructure matches/batches and conformance tests pass.
- Actual CLI generation preserves protected Deployment/Service identity,
  namespace, resources, probe timing, replicas, ports, labels and pull references.
  Fresh workspaces produce stable objects. Multiple containers, Agent annotations
  and revision-specific VSO Secret references are covered locally.
- Normalized input/output-only provisioner parameters contain Secret names/keys,
  never database password bytes. Template-like and substitution-like literal
  values remain data. Protected namespace/foreign Secret patches and malformed
  output are rejected. No database/namespace/PVC is generated by the renderer.
- Frontend/backend/worker acceptance deployments use one shared database Active
  Resource and retain renderer selections after JSON snapshot reopen.
- Pending detects a renderer-only change without a Score draft, rejects an old
  token before provisioning, deploys the current selection, then returns no-op.
  Existing configuration, route retry and remove tests pass.
- The public HTTP flow enforces platform registration role, exposes safe renderer
  provenance in standalone Preview, performs no Preview side effects, and uses
  draft → pending Preview → token-based Deploy successfully.
- Review correction (2026-10-06): resolved non-secret values containing `$`, `$$`,
  `${...}`, `$${...}`, `x$${y}`, multiline/quoted/template-like text and the empty
  string now match the native renderer's env values exactly. Every `$` is escaped
  for score-k8s substitution; an empty value, which score-k8s omits, is restored
  only for the named container/env entry before the unchanged protected-field
  validation. Secret references and identity checks are not relaxed. Covered by
  real-CLI tests `TestRealCLIPreservesResolvedPlainValuesLikeNative` and
  `TestRealCLIRestoresEmptyValueOnlyForNamedContainerAndKeepsSecretRefs`.
- Renderer upgrade A → B (2026-10-06): an existing Definition registered under
  bundle A previews successfully on installed bundle B and pins B; the A token is
  rejected before provisioning, a fresh B token deploys, and pending reports the
  renderer-only change without a draft. Unavailable ID, ties and binary drift
  remain rejected. The registration fingerprint is no longer an equality gate.
- A changed binary fails preflight before provisioning. Generation failure does
  not apply a workload or advance the current Deployment Set.

## Checks

- Backend: `env -u ORCHESTRATOR_POSTGRES_TEST_URL -u ORCH_KIND_VERIFY go test ./...`
  and `go build ./...`.
- Frontend: `npm ci --no-audit --no-fund`, typecheck, lint, **108 tests** and build.
- Documentation: `python3 scripts/check_docs.py`; modified PlantUML sources
  rendered to their tracked PNGs; `git diff --check`.

Live kind/AWS, PostgreSQL mutation and Fleet/VSO readiness verification were
excluded because external verification was not authorized. CLI-dependent tests
skip on hosts without the pinned executable; pure selection/catalog and
synthetic failure/security tests remain runnable without it. Deployment images
require an explicitly provisioned CLI binary to enable this optional feature.
