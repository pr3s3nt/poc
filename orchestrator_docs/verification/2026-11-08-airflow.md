# Apache Airflow through Console — issue #51

## Scope

User asked to try the platform by deploying https://github.com/apache/airflow.
Approved scope: Airflow 3 with LocalExecutor and PostgreSQL on the retained
Console `orchestrator-dev-3070` in `kind-k8s-4f`, authored through Console forms,
one batch Deploy, then sign-in, a DAG run and a task log in the Airflow UI. No
product code changed. Procedure: [scenario README](../../e2e/scenarios/airflow/README.md).

Image `apache/airflow:3.4.0`, pinned by digest. The configuration was first
checked in throwaway local Docker containers (PostgreSQL, migrate, four components,
DAG run, log fetch); those containers were removed and are not acceptance evidence.

## Platform setup required first

The retained Console had only been seeded; no application had been deployed
through it. User approved completing its setup as a Platform Engineer:

- **Vault Kubernetes auth absent.** Added a dedicated token-reviewer
  ServiceAccount with `system:auth-delegator`
  ([manifest](../../deploy/kind-k8s-4f/04-vault-kubernetes-auth.yaml)) and enabled
  mount `kubernetes` on the Console Vault
  ([script](../../deploy/kind-k8s-4f/vault-kubernetes-auth.sh)). VSO then synced the
  PostgreSQL password. The Secret Store page still shows Kubernetes auth as not
  configured: its status is recorded only at registration and cannot be re-verified.
- **No `endpoint` Type.** Registered the Type and an app-scoped endpoint
  Definition on the existing Gateway (routes only, Gateway unchanged).
- **Template mismatch.** The first Preview failed with `PLANNING_REJECTED`
  `renderer-unavailable`. The seeded `git-dev-workload` pins template source commit
  `48035f75`, which this backend lists as UNAVAILABLE (every Git template source is),
  and which lacks templates 1.2.0 and the init/probe capabilities. The Add Workload
  picker nevertheless offered `backend`/`worker` 1.2.0. Registered a Git template
  source pinned to `main` `2755c864` and an app-scoped workload Definition
  (`{app_id, class: git-dev}`, specificity 18 over the shared 17). No draft changed.
- Only `platform-engineer` exists on this Console, so it also performed the
  Developer steps.

## Result

- Four workloads (`api-server`, `scheduler`, `dag-processor`, `triggerer`), each
  with an init container, saved and reopened through UI before Deploy. All select
  one shared PostgreSQL; secrets come from Environment keys and resource outputs.
- Preview contained exactly the four workloads. One UI Deploy request; Operation
  `6a526cb8` **SUCCEEDED** on the first attempt. Fleet namespace access was granted
  as technical setup once the product namespace existed, as in prior trials.
- Read-only cluster checks: namespace UID recorded at creation, four Deployments
  and the PostgreSQL StatefulSet Ready with zero restarts, `DB_PASSWORD` a
  `secretKeyRef` in every main and init container, HTTPRoute Accepted/ResolvedRefs.
- Through the public endpoint over Tailscale: Airflow health reports metadatabase,
  scheduler, triggerer and dag-processor healthy; browser sign-in as the FAB admin
  shows the 121 example DAGs; `example_bash_operator` run succeeded and the
  `runme_0` log is displayed in the UI (fetched from the scheduler by Pod IP).

## Gaps found

1. Template picker offers templates the Environment's matching workload Definition
   cannot render; Preview reports only a generic "template not installed" message.
2. All Git template sources on the upgraded Console are UNAVAILABLE, so the seeded
   workload Definition no longer deploys anything.
3. Secret Store Kubernetes auth status cannot be refreshed after Vault changes.
4. A literal value cannot embed a resource output, so the database URL is composed
   in the container (`SQL_ALCHEMY_CONN_CMD`) from separate `DB_*` references.
5. Shared environment variables are re-entered per container: 14 per container,
   eight containers.
6. Fleet still needs scoped namespace access granted outside the product.

## Checks and limits

`node --check` for both scripts, `bash -n` for the Vault script, Kubernetes server
dry-run of the manifest, documentation checker and whitespace check. Go and
frontend suites were not run: no product code changed. The application, its
PostgreSQL PVC and the endpoint are retained for user review; cleanup must use
Console deletion with namespace UID verification. Platform setup above is retained.
State, screenshots, secrets and the Tailscale link stay outside Git.
